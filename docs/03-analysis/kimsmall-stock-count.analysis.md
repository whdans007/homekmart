## 검증 결과

- PHP 8.3 문법 검사: 신규 화면·API·서비스·마이그레이션 실행기 및 수정된 변경 경로 19개 파일 통과.
- 수량 계산 검사: `3 BOX + 5 PCS`, 입수 12 → 41 PCS; `PACK` 표시; 0개 입력; 반복 스캔 합산 통과.
- 로컬 MySQL 8.4.3의 `u622428657_main`에 신규 테이블과 입고 마감 확인 컬럼 적용, control 행 조회 확인. 기존 미확정 입고 배치 1,203건 때문에 전역 배치 상태를 시작 조건으로 사용할 수 없어 관리자 확인 방식으로 변경.
- 실제 데이터에 대한 조사 시작·확정·취소와 LOT 조정은 실행하지 않음. 사용자가 단계별 점검할 수 있도록 재고를 변경하지 않은 상태로 남김.

## 단계별 운영 점검

1. 관리자: 입고 마감 확인 후 조사 시작. 직원: `BOX`, `PACK` 상품, `PCS` 바코드의 상품 정보 확인.
2. 같은 상품을 여러 번, 다른 날짜에 입력하고 원본 기록과 상품별 합계 확인. 0개 입력, 잘못 입력한 기록의 취소, 미조사 상품 유지 확인.
3. 진행 중 입고·출고·박스 개봉이 거부되는지 확인.
4. 관리자: 확정 전 수량과 차이를 확인하고 확정. LOT별 재고와 조사 이력, 재확정 거부 확인.
5. 별도 조사 건을 시작해 취소 후 입력 기록 보존과 입출고 차단 해제 확인.

## 남은 검증

실제 바코드 스캐너와 로그인 세션을 사용한 브라우저 검증, 테스트용 상품에 대한 확정 트랜잭션 검증이 필요하다. 원가 이력이 없는 초과 재고는 0원 조정 LOT으로 생성되므로 해당 상품의 원가를 사전에 확인해야 한다.
