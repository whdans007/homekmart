## Executive Summary

| 관점 | 설명 |
|------|------|
| **Problem** | 지점 출고 시 아직 재고로 등록되지 않은 상품의 경우 마이너스 재고 상태가 발생하며, 이를 추적하고 관리할 방법이 필요함 |
| **Solution** | 마이너스 재고 허용 시스템 구현: 출고 시 자동으로 음수 재고 생성 → 상품 등록 후 자동 또는 수동 정상화 |
| **Function & UX Effect** | (1) 출고 폼에 미등록 상품 선택 불가 표시 제거, (2) 출고 완료 시 마이너스 재고 자동 생성, (3) 마이너스 재고 상태 시각화 (빨간색 표시), (4) 관리자 대시보드에 마이너스 재고 목록 및 정상화 도구 |
| **Core Value** | 미등록 상품도 즉시 처리 가능 → 운영 유연성 증대, 재고 데이터 무결성 유지, 감사 추적 완전성 |

## 1. 요구사항

### 1.1 기능 요구사항

#### FR-1: 미등록 상품 출고 허용
- 지점 출고 폼에서 미등록 상품도 선택 가능하도록 변경
- 선택 시 경고: "이 상품은 아직 등록되지 않았습니다. 계속하시겠습니까?"
- 출고 기록 시 마이너스 재고 자동 생성

#### FR-2: 마이너스 재고 자동 생성
- 미등록 상품 출고 시: `current_stock = 0 - quantity` (음수)
- 데이터베이스에 기록
- 생성 시간, 출고자, 지점 정보 기록

#### FR-3: 마이너스 재고 상태 표시
- 재고 목록에서 마이너스 수치를 **빨간색**으로 표시
- 아이콘 추가: ⚠️ (경고)
- 상세 보기: 마이너스 재고 발생 이유, 발생 시간, 발생자 표시

#### FR-4: 마이너스 재고 정상화 (혼합 방식)
- **자동 정상화**: 상품이 등록되면 자동으로 대기 중인 마이너스 재고 정상화
  - 예: 상품 등록 → 기존 마이너스 -5 + 신규 입고 = 최종 재고 계산
- **수동 정상화**: 관리자가 수동으로 재고 조정 (상품 부재 등의 경우)
  - 조정 사유 기록 필수

#### FR-5: 추가 출고 정책 (경고 후 선택)
- 마이너스 상태에서 추가 출고 시 경고: "현재 마이너스 재고 상태입니다. 계속하시겠습니까?"
- 경고 후 사용자 선택에 따라 진행

#### FR-6: 마이너스 재고 관리 대시보드
- 관리자 전용 페이지: "마이너스 재고 목록"
- 표시 정보: 상품명, 현재 수량, 발생 시간, 발생자, 지점, 상태 (정상화 대기/해결)
- 액션: 수동 정상화, 이력 조회

### 1.2 비기능 요구사항

#### NFR-1: 성능
- 마이너스 재고 조회: < 500ms
- 정상화 처리: < 1초

#### NFR-2: 데이터 무결성
- 모든 마이너스 재고 변경 사항 감사 로그 기록
- 이중 기록 방지 (중복 정상화 불가)

#### NFR-3: 보안
- 마이너스 재고 수동 정상화는 관리자 권한 필수
- 변경 이력에 변경자 정보 기록

## 5. 구현 전략

### 5.1 개발 순서
1. **데이터 모델**: 재고 테이블에 마이너스 허용 필드 추가 (선택)
2. **출고 로직**: 미등록 상품도 음수 재고로 기록하도록 수정
3. **UI 표시**: 마이너스 재고 빨간색 표시 + 경고 메시지 추가
4. **정상화 로직**: 상품 등록 후 자동 정상화 또는 수동 정상화
5. **관리 대시보드**: 마이너스 재고 목록 + 정상화 도구
6. **감사 로그**: 모든 변경 사항 기록

### 5.2 기술 스택
- Backend: PHP (기존)
- Database: MySQL (기존)
- Frontend: HTML/CSS/JavaScript (기존)

## 6. 검증 계획

### 6.1 테스트 시나리오

**T-1: 미등록 상품 출고**
- 입력: 미등록 상품 선택 → 수량 입력 → 확인
- 기대: 경고 표시 → 재고 -5 저장

**T-2: 자동 정상화**
- 입력: 마이너스 상태 상품 → 상품 신규 등록 → 입고 처리
- 기대: 마이너스 자동 정상화 → 최종 재고 올바르게 계산

**T-3: 수동 정상화**
- 입력: 관리자 로그인 → 마이너스 재고 목록 → 수동 정상화
- 기대: 마이너스 재고 조정 → 이력 기록

**T-4: 경고 후 추가 출고**
- 입력: 마이너스 상태에서 추가 출고 → 경고 확인 후 진행
- 기대: 경고 표시 → 추가 출고 가능

### 6.2 감사 기준
- 모든 마이너스 재고 변경이 로그에 기록되었는가?
- 권한 없는 사용자의 정상화는 불가능한가?
- UI에 정확한 상태 표시가 되어 있는가?
