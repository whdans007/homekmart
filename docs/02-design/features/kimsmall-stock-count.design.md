# BKIT Design: KIM'S MALL 창고 재고조사

**Plan**: `docs/01-plan/features/kimsmall-stock-count.plan.md`
**Implemented**: 2026-09-22
**Scope**: `kimsmall_wherehouse`

## 운영 흐름

1. 관리자만 입고 마감과 조사 중 입출고 중단을 확인하고 조사 건을 시작한다. 확인자와 확인 시각을 기록한다.
2. 직원은 박스 또는 낱개를 선택하고 정확한 바코드를 스캔한다. `BOX` 선택 시 해당 상품의 기존 묶음 LOT 단위가 `PACK`뿐이면 DB에는 `PACK`으로 기록한다.
3. 저장할 때마다 원본 입력 한 건을 보존한다. 날짜별 조회는 입력 시각으로 묶고, 상품별 합계는 유효 입력을 `(product_id, unit)`으로 합산한다. 잘못된 입력은 진행 중인 조사에서 본인 또는 관리자가 취소할 수 있고, 취소 시각·담당자를 남긴다. 0개 입력도 취소하지 않는 한 조사한 단위로 취급한다.
4. 검토 화면은 기준 재고, 조사 수량, 단위별 차이, 낱개 환산 총량을 표시한다. 입력하지 않은 단위와 상품의 재고는 유지한다.
5. 관리자는 확정 또는 취소한다. 확정은 단일 트랜잭션에서 LOT 변경과 감사 이력을 남긴다. 취소는 재고를 변경하지 않고 입력 기록을 읽기 전용으로 보존한다.

## 저장 구조와 단위

`kw_stock_count_control` 단일 행은 진행 중인 조사 건 ID를 가진다. `kw_stock_count_sessions`는 `open/finalized/cancelled` 상태와 담당자·시각을 보존한다. `kw_stock_count_baseline`은 조사 시작 시 상품·단위별 기준 수량을 고정한다. `kw_stock_count_entries`는 바코드, 입력 단위, 수량, 입수, 입력자, 시각과 취소 이력을 보존한다. `kw_stock_count_adjustments`는 확정 시 LOT별 전후 수량과 차이를 기록한다.

`BOX`와 `PACK`은 화면에서 박스로 합산하지만 DB 단위는 합치지 않는다. 낱개 환산은 `BOX 수 × 입수 + PACK 수 × 입수 + PCS 수`다. 동일 상품에 `BOX/PACK` 재고가 혼재하거나 기존 묶음 LOT의 입수가 상품 마스터와 다른 경우에는 해당 상품 입력·확정을 거부해 잘못된 환산을 막는다.

## 동시성·확정

조사 시작, 저장, 확정, 취소와 기존 재고 변경 경로는 모두 트랜잭션 안에서 `kw_stock_count_control`의 단일 행을 `FOR UPDATE`로 잠근다. 조사 중이면 입고·출고·취소·수정·박스 개봉·위치 변경을 거부한다. 확정 전에는 실제 재고와 기준 수량을 다시 비교한다. 확정은 `open` 상태에서 한 번만 가능하다.

부족 수량은 유통기한이 있는 LOT부터 차감한다. 초과 수량은 별도 조사 조정 입고/LOT을 만들고 같은 단위의 최근 입고 원가를 사용한다. 원가 이력이 없는 경우 0원으로 기록하고 입고 비고에 그 사유를 남긴다. 조정 LOT의 유통기한이 비어 있어도 기존 출고·개봉 FEFO에서 유통기한이 있는 LOT이 먼저 선택되도록 `NULL`을 뒤로 정렬한다. 이 원가 정책은 운영 검토 대상이다.

## API와 권한

`ajax/stock_count.php`는 `status`, `sessions`, `lookup`, `list`, `preview`, `start`, `save`, `void_entry`, `finalize`, `cancel`을 제공한다. 조회와 입력 저장은 창고 직원 권한이 필요하다. 본인 입력 취소는 직원에게, 다른 사람의 입력 취소는 관리자에게 허용한다. 시작·확정·조사 건 취소는 관리자 권한이 필요하다. 변경 요청은 POST와 CSRF 토큰을 검증한다.

## 배포·검증

코드 배포 전에 `php kimsmall_wherehouse/sql/run_stock_count.php`로 신규 테이블을 생성한다. 실행기는 이미 설치된 테이블에도 입고 마감 확인 필드를 추가할 수 있다. 변경 후 PHP lint, 수량 계산 테스트, 화면의 날짜별 기록·확정 상태를 확인한다. 실제 재고가 바뀌는 확정 시나리오는 운영 데이터에 임의 실행하지 않는다.
